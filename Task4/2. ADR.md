# ADR № 2
**Тема:** Доставка актуальных депозитных ставок во внутренний и партнёрский кол-центры (MVP)  
**Автор:** Команда цифровой трансформации (ответственный архитектор — *Антон*)
**Дата:** 27 апреля 2025 г.

---

## 1. Функциональные требования (Use Cases)

| № | Действующее лицо / система | Шаги сценария |
|:-:|----------------------------|---------------|
| 1 | **Back-office депозитов** | Подтверждает/изменяет ставку → АБС сохраняет запись. |
| 2 | **Rate Service** | Получает событие об изменении ставки из АБС. |
| 3 | **Rate Distribution Service** | a) Слушает событие `RateChanged` в брокере.<br>b) **Push-отправка** ставки по REST во **внутренний КЦ**.<br>c) Генерация `rates_YYYYMMDD_HHMMSS.csv` и выгрузка на **SFTP** партнёра. |
| 4 | **Платформа внутреннего КЦ** | Принимает REST-запрос, обновляет локальный кеш, показывает ставку оператору. |
| 5 | **Система партнёрского КЦ** | Периодически читает каталог SFTP, парсит CSV, обновляет справочник ставок. |

---

## 2. Нефункциональные требования (NFR)

| № | Требование |
|:-:|------------|
| NFR-1 | Максимальная задержка доставки ставки до обоих КЦ ≤ 60 с. |
| NFR-2 | Доступность Rate Distribution Service ≥ 99,9 % (≈ ≤ 43 мин простоя/мес). |
| NFR-3 | Каналы:<br>• REST — HTTPS/TLS 1.2+;<br>• SFTP — SSH v2, обязательная проверка fingerprint. |
| NFR-4 | Минимум 3 ретрая с экспоненциальной задержкой при сбоях REST или SFTP. |
| NFR-5 | Полный журнал аудита (кто, когда, что отправил) хранится ≥ 1 год. |
| NFR-6 | Только существующий техстек банка: Java 17/Spring Boot, RabbitMQ, MS SQL/Oracle. |
| NFR-7 | Прямых вызовов КЦ → АБС нет. |

## 3. Решение

### 3.1 Диаграмма **C4 — уровень 1 (Context)**

Ссылка на файл: [3. C4_context.puml](3.%20C4_context.puml)

**Пояснение**
1. **Rate Service** уже существует (в первой части проекта) и публикует событие о новой ставке.
2. **Rate Distribution Service (новый микросервис)** получает событие, отправляет данные:
    * **внутреннему КЦ** — по REST PUT `/rates` (быстро, < 1 с);
    * **партнёру** — формирует CSV и кладёт на SFTP.
3. Каждый КЦ обновляет собственный кеш и показывает ставку операторам.

### 3.2 Диаграмма **C4 — уровень 2 (Containers)**

Ссылка на файл: [4. C4_container.puml](4.%20C4_container.puml)

#### Пояснение к диаграмме

| № | Контейнер | Назначение / ответственность | Основной стек | Входящие связи | Исходящие связи |
|---|-----------|-----------------------------|---------------|----------------|-----------------|
| **1** | **AMQP Listener** | • Слушает брокер RabbitMQ по теме `rates.v1`.<br>• Получает событие `RateChanged` от **Rate Service**.<br>• Передаёт сообщение во внутреннюю «рабочую очередь» сервиса. | Spring Boot + RabbitMQ client | `Rate Service → RabbitMQ → Listener` | Локальная очередь (in-mem) |
| **2** | **Internal Push Adapter** | • Забирает событие из очереди.<br>• Формирует JSON и делает `PUT /rates` во **внутренний кол-центр**.<br>• Реализует retry + circuit-breaker. | Spring WebClient | AMQP Listener (внутр.) | HTTPS → Call-center Platform<br>MS SQL Audit DB |
| **3** | **CSV Generator** | • Конвертирует объект ставки в CSV-файл (UTF-8, `;`-разделитель).<br>• Кладёт файл во временный каталог, передаёт путь в очередь для загрузчика. | Spring Boot + OpenCSV | AMQP Listener (внутр.) | SFTP Uploader (внутр.) |
| **4** | **SFTP Uploader** | • Поднимает SSH-соединение (ключ в Vault).<br>• Загружает файл на SFTP-сервер партнёра → atomic rename.<br>• 3 повтора с экспоненциальной задержкой при ошибке. | Spring Boot + JSch | CSV Generator (внутр.) | SFTP-сервер партнёра<br>MS SQL Audit DB |
| **5** | **Audit DB** | • Хранит историю всех попыток доставки (дата, канал, статус SHA-256).<br>• Служит источником метрик для Prometheus / Grafana. | MS SQL 2019 | Internal Push Adapter, SFTP Uploader | Prometheus (read-only) |
| **6** | **Call-center Platform** (внешний контейнер) | • Получает `PUT /rates`, кладёт данные в свой кеш.<br>• Показывает ставку операторам в UI. | Java micro-services | HTTPS от Internal Push | — |
| **7** | **SFTP-сервер партнёра** | • Принимает CSV-файл с актуальными ставками.<br>• Партнёрский КЦ считывает файл cron-скриптом. | OpenSSH SFTP | SFTP Uploader | Партнёрский КЦ (read) |

#### Сквозной поток данных
1. **Back-office** меняет ставку → **АБС** сохраняет запись и шлёт DB-notify.
2. **Rate Service** конвертирует событие в `RateChanged` (RabbitMQ).
3. **AMQP Listener** вписывает событие в очередь задачи.
4. Параллельно запускаются оба конвейера:
    * **Internal Push Adapter** → JSON → *внутренний* КЦ (мгновенно).
    * **CSV Generator → SFTP Uploader** → CSV → *партнёрский* КЦ (≤ 60 с).
5. Оба канала пишут результат в **Audit DB**; метрики видны в Grafana.

> кол-центры не обращаются к АБС и RabbitMQ; вся логика доставки сосредоточена внутри *Rate Distribution Service*, что упрощает сопровождение и снижает нагрузку на core-системы.

## 4. Альтернативы и отказ

| № | Рассмотренный вариант | Причина отказа |
|---|-----------------------|----------------|
| A1 | Встроить REST-API ставок прямо в платформу КЦ | Партнёрский КЦ всё равно требует файл; усложняется безопасность (открытый API наружу). |
| A2 | Делиться таблицей Oracle через DB-link | Нарушение принципа «одна БД — один владелец»; риски нагрузки и безопасности. |
| A3 | Отправлять Excel-файл по e-mail (старый процесс) | Ручная обработка, задержка > 5 мин, высокий риск ошибок ввода. |

---

## 5. Недостатки и риски

* **Зависимость от SFTP-канала** — нет SLA у партнёра → возможны простои > 1 мин.
* **Формат CSV** жёсткий: любое добавление колонки требует согласования с партнёром.
* **RabbitMQ** выбран как быстрый старт; при дальнейшем переходе банка на Kafka понадобится миграция слушателей.
* Если ставка отозвана/исправлена после выгрузки — нужно доп. событие `RateRevoke`, иначе у КЦ останется «ложная» цифра.

## 6. Крупные задачи для планирования

| Система / команда | Основные работы                                                                                                                                                     |
|--------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **АБС (DB-team)** | • PL/SQL-триггер → отправка notify<br>• Утилита «обратный вызов» при отмене ставки                                                                                  |
| **Rate Service (Java-team)** | • Подписаться на notify из АБС<br>• Публикация события `RateChanged` (RabbitMQ topic **rates.v1**)                                                                  |

| **Система партнёрского кол-центра** (внешняя) | • Крон-парсер CSV (автоматический фоновый скрипт через системный планировщик задач cron) → local DB<br>• UI-обновление ставок                                       |
