### Глоссарий сокращений, использованных в FURPS-таблице

| Сокр. | Расшифровка | Пояснение / контекст |
|-------|-------------|----------------------|
| **АБС** | Автоматизированная банковская система | Core-система, где ведутся счета, депозиты, кредиты |
| **ИБ** | Интернет-банк | Онлайн-кабинет клиента |
| **КЦ** | Call-центр | Канал телефонных продаж/поддержки |
| **MVP** | Minimum Viable Product | Минимально-жизнеспособная версия решения |
| **XLS** | eXtensible Length Spreadsheet (файл *.xls) | Формат Microsoft Excel, где сейчас хранятся ставки |
| **SMS** | Short Message Service | Канал отправки уведомлений и OTP |
| **OTP** | One-Time Password | Разовый код подтверждения операции |
| **API** | Application Programming Interface | Способ программного взаимодействия сервисов |
| **БД** | База данных | MS SQL или Oracle в контексте банка |
| **SQL** | Structured Query Language | Язык запросов к реляционным БД |
| **PL/SQL** | Procedural Language/SQL | Процедурное расширение SQL в Oracle |
| **TLS** | Transport Layer Security | Протокол шифрования трафика (v1.2+) |
| **REST** | Representational State Transfer | Стиль организации веб-API |
| **Kafka** | Apache Kafka | Потоковая платформа/брокер сообщений |
| **CDN** | Content Delivery Network | Сеть доставки статического контента |
| **CI/CD** | Continuous Integration / Continuous Delivery | Автоматические сборка, тесты и выкатывание |
| **HPA** | Horizontal Pod Autoscaler | Механизм горизонтального масштабирования в Kubernetes |
| **RPS** | Requests Per Second | Метрика «запросов в секунду» (нагрузка) |
| **KPI** | Key Performance Indicator | Ключевой показатель эффективности |
| **UI** | User Interface | Пользовательский интерфейс |
| **Dev / Stage / Prod** | Development / Staging / Production | Среды разработки, теста, промышленной эксплуатации |
| **MS SQL** | Microsoft SQL Server | Реляционная СУБД, используемая в банке |
| **.NET** | Microsoft . NET Framework | Платформа, на которой написан интернет-банк |
| **2 ЦОД** | Два Центра обработки данных | Основной и резервный дата-центры |
| **Vault** | (Secret) Vault | Система защищённого хранения секретов/паролей |
| **152-ФЗ** | Федеральный закон РФ № 152-ФЗ «О персональных данных» | Базовый норматив по ПДн в России |


> 🟠 **Оранжевым (и жирным)** помечены **архитектурно-значимые** пункты

| Код | Требования | Комментарий |
|-----|------------|-------------|
| **F** | **Функциональные (Functionality)** | |
| F-1 | Клиент **на сайте** просматривает перечень депозитов с актуальными ставками и отправляет заявку (Ф. И. О., телефон). | Базовая функция MVP для нового клиента. |
| <span style="color:#ff5722"><strong>F-2</strong></span> | <span style="color:#ff5722"><strong>Сайт автоматически создаёт обращение в системе call-центра; оператор видит заявку и звонит клиенту.</strong></span> | Интеграция сайта ↔ платформа КЦ, влияет на схему обмена событиями. |
| <span style="color:#ff5722"><strong>F-3</strong></span> | <span style="color:#ff5722"><strong>В интернет-банке клиент видит депозитные продукты с персонализированными ставками.</strong></span> | Требует сервиса расчёта/кэширования ставок вне XLS. |
| <span style="color:#ff5722"><strong>F-4</strong></span> | <span style="color:#ff5722"><strong>Клиент ИБ указывает счёт, сумму и подтверждает заявку одноразовым SMS-кодом (OTP-сервис внутри банка).</strong></span> | Избегаем дорогих доработок подрядчика и зависимости от ядра ИБ. |
| <span style="color:#ff5722"><strong>F-5</strong></span> | <span style="color:#ff5722"><strong>Заявка регистрируется в АБС, но в MVP обрабатывается вручную; статусы передаются клиенту по SMS.</strong></span> | Нужна двусторонняя интеграция через очередь/шину, без прямых вызовов. |
| F-6 | Сотрудник бэк-офиса может назначить спец-ставку, подтверждённую кредитным аналитиком. | Требует процесса согласования и хранения ставок в БД/АБС. |
| **U** | **Удобство использования (Usability)** | |
| U-1 | Единый дизайн-кит (бренд банка) для сайта и ИБ. | Гарантирует консистентный UI; переиспользуем React-компоненты. |
| <span style="color:#ff5722"><strong>U-2</strong></span> | <span style="color:#ff5722"><strong>Время загрузки экранов ≤ 1 с, отклик по действиям ≤ 200 мс.</strong></span> | Требует кешей, read-replica БД и CDN; влияет на фронтовую/бэковую архитектуру. |
| U-3 | Адаптивная вёрстка (desktop, tablet, mobile). | KPI «удобный интерфейс». |
| **R** | **Надёжность (Reliability)** | |
| <span style="color:#ff5722"><strong>R-1</strong></span> | <span style="color:#ff5722"><strong>Доступность сервисов ≥ 99,9 % (≤ 43 мин простоев/мес).</strong></span> | Требует 2 ЦОД, отказоустойчивых кластеров, health-check. |
| <span style="color:#ff5722"><strong>R-2</strong></span> | <span style="color:#ff5722"><strong>Работа 24 × 7, включая нагрузочные пики.</strong></span> | Горизонтальное масштабирование фронтов, очереди между каналами и АБС. |
| <span style="color:#ff5722"><strong>R-3</strong></span> | <span style="color:#ff5722"><strong>Внутренний сервис SMS-OTP ≥ 99,95 % доступности.</strong></span> | Критично для завершения транзакций. |
| <span style="color:#ff5722"><strong>R-4</strong></span> | <span style="color:#ff5722"><strong>При недоступности АБС заявки надёжно ставятся в очередь и обрабатываются после восстановления.</strong></span> | Требует брокер сообщений и механизм retry. |
| **P** | **Производительность (Performance)** | |
| <span style="color:#ff5722"><strong>P-1</strong></span> | <span style="color:#ff5722"><strong>Генерация персональной ставки ≤ 100 мс.</strong></span> | Нужны in-memory cache и асинхронное обновление. |
| <span style="color:#ff5722"><strong>P-2</strong></span> | <span style="color:#ff5722"><strong>Система обрабатывает ≥ 50 заявок/сек без деградации.</strong></span> | Задает параметры стресс-тестов, размеры пулов и HPA. |
| P-3 | Шифрование не увеличивает 95-й перцентиль задержки > 50 мс. | TLS off-load на балансаторах. |
| **S** | **Поддерживаемость (Supportability)** | |
| S-1 | Swagger/OpenAPI-документация + вики для новых сервисов. | Нужно для дальнейшего расширения. |
| <span style="color:#ff5722"><strong>S-2</strong></span> | <span style="color:#ff5722"><strong>CI/CD-пайплайны с авто-тестами (Dev → Stage → Prod).</strong></span> | Влияет на структуру репозиториев и инфраструктуру. |
| <span style="color:#ff5722"><strong>S-3</strong></span> | <span style="color:#ff5722"><strong>Техстек ограничен Java/.NET + MS SQL / Oracle.</strong></span> | Определяет выбор фреймворков и ORM. |
| <span style="color:#ff5722"><strong>S-4</strong></span> | <span style="color:#ff5722"><strong>Развёртывание в контейнерах, поддержка горизонтального autoscaling.</strong></span> | Задает схему кластеризации (Kubernetes/Openshift). |
| **+R** | **Ограничения (Restrictions)** | |
| <span style="color:#ff5722"><strong>+R-1</strong></span> | <span style="color:#ff5722"><strong>ИБ не обращается напрямую к API/БД АБС; вся интеграция через шину/прослойку.</strong></span> | Снижает нагрузку на АБС, повышает изоляцию отказов. |
| <span style="color:#ff5722"><strong>+R-2</strong></span> | <span style="color:#ff5722"><strong>Весь трафик шифруется TLS 1.2+; секреты — в защищённом vault.</strong></span> | Соответствие 152-ФЗ |
| <span style="color:#ff5722"><strong>+R-3</strong></span> | <span style="color:#ff5722"><strong>Текущий ИБ не поддерживает Kafka; прослойка должна уметь fallback на REST или внутренние очереди.</strong></span> | Влияет на выбор интеграционного паттерна. |
| <span style="color:#ff5722"><strong>+R-4</strong></span> | <span style="color:#ff5722"><strong>АБС масштабируется только вертикально → ограничиваем запросы, применяем кэши и circuit-breaker.</strong></span> | Требует слой троттлинга и bulk-head. |
| +R-5 | Используются только лицензионные СУБД MS SQL / Oracle (open-source БД — лишь для кешей/очередей). | Соответствие внутренним стандартам лицензирования. |
| +R-6 | SMS отправляются через существующий шлюз, без изменения ядра ИБ. | Снижает стоимость и риск подрядных работ. |
